# Glossary

Quick reference for acronyms and Dutch terms used in this repository. Aimed at international participants and reviewers from outside procurement.

## Organisations

| Term | What it is |
|---|---|
| **DACC** | Digitale Autonomie Competentiecentrum: collaboration of, among others, AMS Institute, VNG, Digicampus, the Ministry of the Interior, TU Delft and the City of Amsterdam, developing tools for digital autonomy in the public sector |
| **VNG / VNG Realisatie** | Association of Netherlands Municipalities and its implementation organisation |
| **IBD** | Informatiebeveiligingsdienst: the information security service for municipalities |
| **BZK** | Ministry of the Interior and Kingdom Relations |

## Procurement

| Term | What it is |
|---|---|
| **Aanbesteding** | Public tender |
| **Bestek** | Tender documents |
| **PvE** (*programma van eisen*) | Programme of requirements, part of the tender documents |
| **Eis** | Requirement: knock-out; offers that do not meet it are excluded |
| **Gunningscriterium** | Award criterion: scored to compare offers that meet the requirements |
| **Proportionaliteit** | Proportionality: requirements must be in proportion to the contract |
| **Inkoper** | Buyer / procurement officer |
| **TenderNed** | The Dutch government's online tender platform |
| **GIBIT** | Gemeentelijke Inkoopvoorwaarden bij IT: municipal IT purchasing conditions |
| **HenT** | Hosting en Technisch applicatiebeheer: a hosting tender of the City of Amsterdam, used as a practice reference |

## Digital autonomy and sovereignty

| Term | What it is |
|---|---|
| **Digitale autonomie** | The ability of a government body to make its own choices about technology and to switch when a supplier fails or no longer fits |
| **Soevereiniteit** | Control: being subject only to the intended legal order, with effective control over data, operations and technology |
| **ECSF / CSF** | (European) Cloud Sovereignty Framework of the European Commission |
| **SOV-1 to SOV-8** | The eight sovereignty objectives of the CSF |
| **SEAL-0 to SEAL-4** | Sovereignty Effectiveness Assurance Levels of the CSF |
| **Extraterritoriale wetgeving** | Laws of a non-EU country that can reach data or providers inside the EU |
| **Autonomy washing** | Presenting a partial or cosmetic measure as real autonomy |
| **SaaS / PaaS / IaaS** | Software, Platform and Infrastructure as a Service |

## Information security and architecture

| Term | What it is |
|---|---|
| **BIO2** | Baseline Informatiebeveiliging Overheid, version 2: the security baseline for Dutch government |
| **NIS2 / Cbw** | EU directive on network and information security; implemented in the Netherlands by the Cyberbeveiligingswet |
| **PLC** | Proportioneel Leveranciers- en Contractmanagement (IBD) |
| **GEMMA** | Municipal reference architecture |
| **NORA** | Dutch government reference architecture |
| **DPIA** | Data protection impact assessment |
| **Kritiek proces** | Critical process: a process whose disruption has serious consequences; see the IBD list |

## Data

| Term | What it is |
|---|---|
| **AVG** | Dutch name of the GDPR |
| **Persoonsgegevens** | Personal data |
| **Bijzondere persoonsgegevens** | Special categories of personal data (for example health) |
| **Woo** | Wet open overheid: Dutch open government act |
| **Archiefwet** | Dutch archives act |

## This challenge

| Term | What it is |
|---|---|
| **Classificatietoets** | The questionnaire this challenge builds on: process and data classification in five steps |
| **Profiel** (profile) | Outcome of the toets for one process or data element: process criticality, B, I, V |
| **BIV** | Beschikbaarheid, Integriteit, Vertrouwelijkheid: availability, integrity, confidentiality |
| **Kritiek / Kern / Ondersteunend** | The process criticality levels in the toets |
| **Openbaar / Vertrouwelijk / Geheim** | The confidentiality levels in the toets |
| **Stamdata / basisregistratie** | Master data and base registers; critical by definition when a process uses them |
| **RTO / RPO** | Recovery time objective / recovery point objective (question B7) |
| **Rules-as-code** | Decision rules written as code or configuration that can be read, tested and versioned |
